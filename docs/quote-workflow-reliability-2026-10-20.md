# Quote workflow reliability

The Quotes page separates Robinhood authorization, private service access, successful requests, and per-contract quote checks. Check connection status reads stored authorization; it does not fetch prices. Failed batch loads preserve the existing batch and observations. Network and service errors no longer imply that Robinhood authorization expired. Confirmed sign-in and authorization failures have separate recovery guidance.

Retry is manual and repeats the selected batch, metadata, quote or status action. There are no automatic quote retries or polling. Candidate/status/quote requests time out after 30 seconds; exact metadata matching allows 120 seconds. The deadline covers both the fetch and the response body. Connections uses the same request handling; Plaid sync allows 120 seconds and other account requests 20 seconds. Public account-review history fetches have 15-second deadlines.

Exports and tab recovery retain up to 200 request diagnostics, including failures before any batch was loaded. Only operation, outcome code, start/end clocks, browser duration and HTTP status are allowed. No request bodies, raw error messages, tokens, authorization headers, account records or holdings are included. A successful HTTP/JSON response is separate from complete contract observations or passing checks. Older exports lack these diagnostics and cannot establish a failure rate.

Capture countdowns show opens/closes times and captured/missing states per contract at 5, 10 and 15 minutes from its original first passing receipt. Provider timestamps must fall in the target through target+60-second window. A failed quote check cannot complete the window. Old provider timestamps and late taps can leave a window missing. A reload preserves the original cutoff; no backfill is performed. Countdown updates may pause when the phone is backgrounded. Price labels separately state within $0.30, above budget or unknown because the quote check failed.

Verification uses synthetic private responses and failure cases. It covers stalled fetches and bodies, separate sign-in/network/authorization/service failures, explicit retry, failure-only exports and reloads, preserved evidence after failed batch replacement, per-contract capture windows and friendly price labels. These tests do not establish provider availability, actual exchange latency, executions or ranking performance. The next owner-operated open-market collection remains necessary.
